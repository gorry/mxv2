## 最初の目標
- mxv/ に、WindowsでMXDRV用音楽ファイル（MDX）をビジュアライズ付きで演奏するシステム mxv があります。これを現代化した「mxv2」を作成したいと考えています。
- 演奏モジュールは portable_mdx/ を使用します。
- 入出力まわりはSDL2を使用します。
- ビジュアライズの方式とリソースはmxvのものを可能な限り継承します。
- まずはWindows用プレイヤーを目標としますが、最終的にはAndroidネイティブ用やEmscripten経由でのWebプレイヤーをターゲットに考えます。

## 更新プラン
- ファイラーと曲名表示をWindowsのMSゴシック内ビットマップフォントに頼らず、任意のttfフォント（等幅・プロポーショナルとも可能）でレンダリングできるようにします。（完了済）
- 表示スキンをフォルダ形式（skin/*）で複数持ち、切り替え可能にします。（完了済）
  - 現在ウィンドウが640x480px固定、コード内埋め込みになっている「各種表示コンポーネントやボタン類の座標」を、スキン側に持たせるようにします。（完了済: `layout.ini`）
  - 現在の表示用アセット（ビットマップ）や座標類をスキン「Default」として作成・移動します。（完了済: `assets/skin/Default/`）
  - ユーザーフォント（font.ttf）も、スキン側に持たせるようにします。（完了済: スキンの font.ttf が最優先）

### 素材と設定の置き場所

素材は 2 か所に分かれる。

| 場所 | 中身 | 書き込み |
|---|---|---|
| `<実行ファイル>/assets/` | 同梱ぶん（スキン・同梱フォント・同梱曲 `mdx/`） | **しない** |
| ユーザーフォルダ | `mxv2.ini`・ユーザーが足したスキン・保存した配色・`font.ttf`・曲 `mdx/` | する |

ユーザーフォルダは OS ごとに決まる。

| OS | 場所 |
|---|---|
| Windows | `%APPDATA%\mxv2\` |
| macOS | `~/Library/Application Support/mxv2/` |
| その他の Unix | `$XDG_DATA_HOME/mxv2/`（無ければ `~/.local/share/mxv2/`） |
| Android / Web | アプリの内部ストレージ |

同梱ぶんを書き換えないのは、アプリを入れ替えると消えるうえ、
Android の apk の中や Program Files の下はそもそも書けないため。
[配色設定] (F2) の「保存」は、同梱スキンを編集していても
ユーザーフォルダ側の `skin/<名前>/colors.ini` へ書く。
**名前を変えれば「名前を付けて保存」**になり、今のスキンを土台
(`Base`) にした新しいスキンができて、そのスキンへ切り替わる。
すでにある名前のときは上書きの確認が出る。

`font.ttf` のようなルート直下のファイルは両方を見て、
**ユーザーフォルダのほうが優先**される。ただし `font.ttf` が効くのは
**キャンバスの文字だけ**で、**設定などのダイアログは必ず同梱の
`MPLUS1p-Regular.ttf`** を使う（ダイアログの寸法は同梱フォントを前提に
決めてあるため）。
どちらの場所も `-assets <dir>` / `-userdir <dir>` で変えられる。

### メッセージカタログ

画面とログに出す文言はコードに直接書かず、
`assets/locale/<ロケール>/message.ini` にまとめてある。

言語は**設定ウィンドウの一番上の [言語]** で選ぶ。一覧に出るのは
**同梱ぶんとユーザーフォルダの `locale/` にあるもの**で、その言語自身での
呼び名（`[Locale] Name`）で並ぶ。**選んだ言語はその場で反映される**
（起動し直さなくてよい）。既定は「自動（環境に合わせる）」で、動作環境の
言語に一番近いものを使う（`ja` しか分からない環境でも `ja-JP` が選ばれる。
合うものが無ければ `en`）。

**言語はユーザーが足せる。** ユーザーフォルダに

```
locale/<ロケール名>/message.ini
```

を置くと、次の起動から [言語] の一覧に出る（一覧を作るのは起動時に 1 度だけ）。
名前の付け方は 2 通り:

- **同梱と同じ名前**（`ja-JP` など）… その言語に**重ねる**。変えたいキーだけ
  書けばよく、全部を写す必要はない。呼び名を書き直せば一覧の表示も変わる。
- **同梱に無い名前**（`fr-FR` など）… **新しい言語**として一覧に出る。
  書いていないキーは落とし先の `en` から出る。`[Locale] Name` にその言語での
  呼び名を書いておくとよい（無ければフォルダ名がそのまま出る）。

どちらもファイルの置き場所は同じで、**同じ名前が両方にあれば 1 つにまとまる**
（フォルダ名の綴りは同梱ぶん、呼び名はユーザーぶんが勝つ）。

選んだ言語は `mxv2.ini` の `[UI] Locale` に残る（「自動」は空）。決め方は
**`-locale <name>` → `[UI] Locale` → 動作環境の言語**の順で、`-locale` は
ini に残さない（一時的な指定なので）。

同梱しているのは `ja-JP` と `en` の 2 つ。**`en` は `ja-JP` からの AI 自動翻訳**で、
人の目は通っていない（その旨をファイルの先頭にも書いてある）。

読む順は

1. 落とし先 `en`（同梱 → ユーザーフォルダ）
2. 頼まれたロケール（同梱 → ユーザーフォルダ）

で、後から読んだものが**キー単位で**勝つ。変えたいキーだけ書けばよく、
全部を写す必要はない。**知らないロケール名を渡されても英語で出る**
（`-locale xxx` なら警告を 1 行出して `en` を使う）。

ただし `[UsageOptions]` `[HelpKeys]` `[HelpMouse]` の 3 つは**一覧**なので、
言語をまたぐときはキー単位で混ぜず、**頼まれたロケールが定義していれば
その一覧で丸ごと置き換える**（左側まで訳の対象なので、混ぜると英語と
日本語が並んでしまう）。同じロケールの中（同梱の上にユーザーぶん）では、
今までどおり行の差し替えと追加ができる。

| 決めごと | 中身 |
|---|---|
| 何を置くか | **訳す必要のある文言だけ**。オプション名 (`-zoom`) やログの接頭辞 (`warning  : `) のような構文はコードに残す |
| 引数 | `{0}` `{1}` … で入れる。符号や小数点以下の書式はコード側で作る |
| 一覧のセクション | `[UsageOptions]` `[HelpKeys]` `[HelpMouse]` は「左=右」の 2 段組で、**書いた順にそのまま出る**。左側も表示に使う |
| ダイアログの題名 | `[Dialog]` の値に `###` を足さないこと（ImGui の内部 ID の区切り） |
| 空白 | 値の前後の空白は落ちる（区切りが要るところはコード側で足している） |
| 無いキー | キー名がそのまま画面に出て、ログに `message not found: <キー>` が 1 度出る |
| 改行 | 値の中の `\n`（バックスラッシュ + n）が改行になる。他のエスケープは無い（パスの `\` はそのまま） |

`-h` の出力と [操作方法] ダイアログは同じ `[HelpKeys]` `[HelpMouse]` から
組み立てる。桁揃えは全角を 2 と数えた表示幅で、一番広い項目に合わせる。

### ファイルシステム

ファイラーのルートの 1 段上に「ファイルシステムの選択」がある。
BACKSPACE でルートから 1 つ上がる（`\` は今いるファイルシステムの
ルートへ跳ぶ）。ここから曲の置き場所を選ぶ。

| 表示 | 中身 | 根にするフォルダ |
|---|---|---|
| `Bookmarks>` | ブックマーク（ジャンプ専用の一覧。「ブックマーク」の節） | なし（`bookmark:` だけ） |
| `Assets>` | 同梱アセット | `<実行ファイル>/assets/mdx/` |
| `UserDir>` | ユーザーフォルダ | `<ユーザーフォルダ>/mdx/`（無ければ作る） |
| `Local>` | ローカルファイルシステム | ドライブのルート |

`DIR>` は**フォルダマウント**で、OS ネイティブの任意のフォルダを根にする。
[ファイルシステムの設定] の [追加...] から足す。場所は **OS のパスを打ち込むか、
[参照...] で OS の「フォルダを探す」ダイアログ**から取る（ファイラーの
[フォルダを開く] は VFS の中を辿る別物なので、ここでは使わない）。
Windows の UNC (`\\server\share\...`) もそのまま根にできる。

末尾の `[Setting]` は [ファイルシステムの設定] を開く（F3 と
右クリックメニューからも開く）。ここで並び順を変えられる。
上の 3 つは**初回起動時から使えるので削除できない**。SAF (Android) や
Web・SMB といった外部ファイルシステムを足せるようにする予定で、
[追加] はそれまでグレーアウトしている。

場所の指定は接頭辞付きの 1 本の書き方に揃えてある。`mxv2.ini` の
`[Filer] LastDir` と `[Path] PDX`、コマンドラインの引数と `-pdxpath`
のどれでもこの書き方が使える。

| 書き方 | 指すもの |
|---|---|
| `assets:<パス>` | 同梱アセットの `mdx/` から見た場所 |
| `userdir:<パス>` | ユーザーフォルダの `mdx/` から見た場所 |
| `localfs:<パス>` | ローカルのフルパス（`localfs:` だけならシステムドライブのルート） |
| `dir:<パス>` | フォルダマウント。OS ネイティブの任意のフォルダを根にする |
| 接頭辞なし | ローカルのパス。相対パスはカレントディレクトリから |

接頭辞は「2 文字以上の英字 + `:`」なので、`C:\mdx` のような
ドライブレターと取り違えることはない。**同じ種類のファイルシステムを
複数マウントできる**ように、ref はスキームだけでなく場所まで見て
どのマウントのものかを決める（`mxv2.ini` の `FS<n>` も、場所を持つものは
`<スキーム>:<場所>` の形で書く）。`layout.ini` の
`[Skin] Base=assets:<名前>` は綴りが同じだけの別物（スキン名の修飾）。

ファイラーに出す MDX のタイトルは、**別スレッドが読んで少しずつ埋める**。
フォルダを開くとその中の MDX を全部開くことになるので、外部ファイル
システムでは 1 曲 1 リクエストになり、メインスレッドで読むと開いた瞬間に
画面が固まる。フォルダを移ると読みかけのぶんは捨てられる（世代番号で
見分けているので、前のフォルダのタイトルが混ざることはない）。

`mxv2.ini` から捨てた項目（知らないファイルシステム、行き先が無くなった
ブックマーク）や、スキン・フォントの取りこぼしは、**起動直後に
[起動時の警告] ダイアログ**でまとめて知らせる。ウィンドウが開く前の
できごとなので、ログに出すだけでは気付けないため。同じ内容はログにも出る。

PDX は「MDX と同じフォルダ →
そのファイルシステムのルートの `pdx/` → `-pdxpath` や設定の探索先」
の順に探す。真ん中はローカルファイルシステムでは飛ばす。

### ブックマーク

よく開く場所を控えておいて、そこへ一足で移れる。入口は 2 つある。

- **ファイラーの `Bookmarks>`**（M、またはメニューの [ブックマークを開く]）。
  ファイルシステムの選択の最上部に並ぶ、**ジャンプ専用**の一覧。控えた
  場所が登録順に並び（ファイル名の位置は行き先のフォルダ名、曲名の位置は
  行き先の全体）、選ぶとそこへ移る。移ったあと BACKSPACE で戻るのは
  行き先の親であって `Bookmarks>` ではない。末尾の `[Setting]` から下の
  ダイアログが開く。ref は `bookmark:`（場所はルートだけ）。
  [ファイルシステムの設定] で順番は変えられるが削除はできず、ini に
  無ければ先頭に足される。`Bookmarks>` 自身は控えられない。
- **[ブックマークの設定]**（F4、またはメニューの [ブックマークの設定]）。
  こちらは**管理が主**で、選んだ場所をメイン画面のファイラーで開くことも
  できる（ダブルクリックでも開く）。並べ替え・追加・削除はここで行う。
  [追加] はカレントフォルダを**選択位置へ挿し込む**。

初回起動時（ini に `[Bookmark]` が無いとき）は `assets:` が 1 つ入っている
（消してよい。特別扱いはしない）。

Shift+M はカレントフォルダの控え / 控え外しで、控えてあれば削除、
無ければ**末尾へ追加**する。どちらも確認してから実行する。
右クリックメニューにも同じものがある。

ファイルシステムの選択（ルートの 1 段上）は控えられない。

控えは `mxv2.ini` の `[Bookmark]` に、ファイルシステムの一覧と同じ形で
並ぶ。中身はファイルシステムの節にある ref。

```
[Bookmark]
Count=3
Bookmark1=assets:
Bookmark2=userdir:
Bookmark3=localfs:C:\MDX
```

読み込み時に知らないファイルシステムが書かれていれば、警告して捨て、
そのぶんを書き戻す。**行き先まで実在するかどうかは見ない**（時間が掛かるし、
外付けが外れているだけかもしれない）。開けなかったときはダイアログに
その旨を出し、閉じずに残る（`Bookmarks>` から開いたときは一覧に留まるだけ）。
控えた先がファイルになっていたときは「そのファイルのあるフォルダ」へ
控え直してから開く（どちらの入口でも同じ）。

### チュートリアル

初回起動時（`mxv2.ini` に `[Tutorial] Done=1` が無いとき）に、使い方を
案内するチュートリアルが始まる。画面に半透明の幕を掛け、注目する部品だけ
明るく残して吹き出しで説明する。「やってみる」の段は、実際にその操作が
起きると自動で次へ進む。いつでも [スキップ] で抜けられる（ESC / 戻るキーも
同じ。確認が 1 回出る）。見終えるかスキップすると `Done=1` が書かれ、
以後は出ない。もう一度見るには、設定ウィンドウ (F1) の [動作] にある
「次回起動時にチュートリアルを表示する」を入れる（`Done` の裏返し）。
曲を指定して起動したときは出ない。`-tutorial` は見終えていても出す（デバッグ用。
終わっても `Done` は触らない）。シナリオは `tutorial.md`。

### CONT / REPEAT の記憶

メイン画面の [CONT]（自動で次の曲へ）と [REPEAT]（自動で繰り返す）の
入り切りは `mxv2.ini` の `[Play]` の `Cont` / `Repeat` に残り、次の起動でも
そのまま点いた状態で始まる。キー（C / R）でもボタンでも、どちらで
切り替えても記録される。

### ファイラーの横スワイプ

指（マウス）で**横へはじく**と、キーボードの ENTER / BACKSPACE と同じことが
できる。スマートフォンでキーボードが無いときのための操作。

| | |
|---|---|
| 右へはじく | カーソル位置を開く（ENTER と同じ。曲なら演奏、フォルダなら移動） |
| 左へはじく | 親フォルダへ移動（BACKSPACE と同じ） |

どちらも**カーソルは動かない**。キーボードの ENTER / BACKSPACE を指で
行うための操作なので、はじいた場所ではなく今のカーソルが対象になる。

**はじいたときだけ**効く。ゆっくり横へずらしただけ、縦に振ったついでに横が
ぶれただけ、指を止めてから離した、のどれでも動かない。上下にはじいたときは
今までどおり慣性スクロール。滑っているのを止めるために触ったときは、
どちらも起きない。

### 曲名の横スクロール

曲名が枠に収まらないときは、横へスクロールして最後まで見せる。
Phone のような横幅の狭いスキンのためのもので、**収まっているときは動かない**。

- 先頭を出したまま待つ
- 末尾が出るところまで送る
- 末尾を出したまま待つ
- 先頭へ戻って繰り返す

送る速さは**文字の高さの何倍を 1 秒に送るか**で決まり、画素では決めない
（解像度やスキンの字の大きさで読める速さが変わらないように）。基準は
「文字の高さ × 40/24 ドット/秒」で、スキンの `[Title] ScrollSpeed`（曲名欄）と
`[FileList] ScrollSpeed`（ファイラー。小・大の別なし）が % でこれに掛かる
（1〜1000、100 が基準）。同梱スキンは曲名欄 100、ファイラー 150 で、
どちらも Phone スキンを Pixel 7a で見たときの速さに合わせてある。

止まっている長さは**画面下の曲名欄が 3 秒、ファイラーが 1 秒**。
曲を変えたときと、スキンや配色を変えたときは先頭からやり直す。

**ファイラーの曲名**は [mxv2 の設定] の [ファイラー] にある
**[曲名スクロール]** で選ぶ。

| | |
|---|---|
| しない | 桁からはみ出したところは今までどおり出さない |
| カーソル行だけ | カーソルのある行だけ送る（既定） |
| 全て | 桁に収まらない行を全部送る |

**送り位置は行ごとに独立して持つ。** 画面に見えている行だけが動き、
**縦にスクロールして画面から外れた行はその場で止まって待つ**（戻って
くると続きから流れる）。先頭からやり直すのは、**カーソルが来た行**と、
フォルダを移ったときだけ。`mxv2.ini` では `[Filer]` の `TitleScroll`
（0/1/2）。

### バックグラウンド演奏（Android）

Android では、ホームに戻ったり画面が消えたりしても**演奏を続ける**。
画面を描くのだけを止め、演奏・CONT（自動で次の曲へ）・REPEAT（自動で
繰り返す）はそのまま動く。

演奏しているあいだは通知が出る。

- 曲名と状態（演奏中 / 一時停止中）、CONT・REPEAT が入っていればその印
- ボタンは [前の曲] [一時停止 / 再開] [次の曲] [停止]
- 通知をタップするとアプリの画面へ戻る
- ロック画面や Bluetooth のリモコン（メディアキー）からも同じ操作ができる

[■]（停止）で演奏を止めたときと、演奏し終えて次が無いときは通知も消える。
アプリを終了すればもちろん消える。

次のときは自動で一時停止する。

- 電話や他のアプリが音を鳴らし始めたとき（終わって音が戻ってくれば、
  こちらで止めたぶんだけ演奏を再開する）
- ヘッドホンが抜けたとき（スピーカーで鳴り出さないように）

通知は Android 13 以降だと許可が要るので、初回起動時に一度だけ尋ねる。
断っても演奏は続くが、通知が出ないぶん OS にアプリを止められやすくなる。

### ステータス欄の長押し（音色データ表示）

ステータス欄（各チャンネルの音量や LFO の値が出る欄）を長押しすると、
表示が「音色データ」に切り替わる（もう一度長押しで戻る。マウスでも指でも同じ。
メニューの [表示] > [音色データ] と F7 でも切り替えられる）。
FM の各段には、アルゴリズムとフィードバック（"A0" / "F0"）と、4 つのオペレータの
AR / DR / SR / RR / SL / TL / KS / MUL / DT1 / DT2 / AME を 16 進で並べる。
オペレータの段は上から M1 / C1 / M2 / C2（MML の OP1〜OP4 の順。`layout.ini` の
`[Status] OPMOperatorY` で入れ替えられる）。PCM の段には OPM 全体の値
（NOISE / CLKB / LFRQ / PMD / AMD / WAVE）を出す。TL だけは音色データの値で、
残りは MXDRV が OPM へ書いたレジスタの値（tonedata.md）。
どちらを表示しているかは保存せず、起動時は常にチャンネルステータスから始まる。
各項目の位置は `[Status]` の `PosOPM*`（同梱スキンの `layout.ini` を参照）。

### 鍵盤の長押し（OPM レジスタ一覧）

鍵盤を長押しすると、今の画面の上に OPM の全レジスタ（$00〜$FF）の値を
16 進で並べたオーバーレイが出る（もう一度長押しで消える。マウスでも指でも同じ。
メニューの [表示] > [OPM レジスタ一覧] と F8 でも切り替えられる）。
並びは regmap.md のとおりで、上から LFO / KEY / NOISE の段、CLKA / CLKB / TIMER /
LFRQ / PMD・AMD / WAVE の段、チャンネルごとの AL/FB・KC・KF・PMS/AMS、
オペレータごとの DT/ML・TL・KS/AR・AM/DR・D2/SR・SL/RR。右端がその行の
レジスタ番号の先頭。値は MXDRV が OPM へ書いたものの写しで、$19 は PMD / AMD の
どちらであれ最後に書かれた値（bit7 で見分けられる）。MXDRV が書かないレジスタ
（CLKA など）は 00 のまま。
表示中もクリック・タップはオーバーレイを素通りして下の部品に届く（鍵盤の
短押しでマスクが変わる）。表示しているかは保存せず、起動時は常に消えている。
矩形と文字の位置は `layout.ini` の `[RegMap] Rect` / `Pos`、色は `colors.ini` の
`[RegMap]`（[配色設定] の「OPM レジスタ一覧」）。文字はミニフォントで 56 桁 x 25 行
（行送りは `[MiniFont] Height` + 1px）。

### スキンの構成
```
skin/<名前>/
    layout.ini   画面サイズ・各部品の座標・素材のファイル名。
                 [Skin] Base=<指定> で他のスキンを土台にできる
                 （土台の土台も辿る）
    colors.ini   配色（[配色設定] で編集・保存できる）
    font.ttf     文字描画に使うフォント（省略時は同梱フォント）
    *.bmp        素材ビットマップ（省略時は Base のフォルダから読む）
```
`skin/` は `assets/` とユーザーフォルダの両方にある。スキンを足すときは
ユーザーフォルダ側の `skin/` へフォルダごと置く。

**1 つのスキンはどちらか一方のフォルダのもの**で、混ざることはない。
同じ名前のスキンが両方にあってもよく、指定のしかたで区別する。

| 指定 | 指すもの |
|---|---|
| `<名前>` | ユーザーフォルダの `skin/<名前>`。無ければ同梱の `skin/<名前>` |
| `assets:<名前>` | 同梱の `skin/<名前>` を名指し |

一覧（F1 の「スキン」）には、ユーザーぶんが名前のまま、同梱ぶんが
`assets:` 付きで並ぶ。`-skin` と `layout.ini` の `Base` も同じ書き方。
**`Base` で同梱ぶんを土台にするときは `assets:` を付けること。**
付けないと、同じ名前のユーザースキンを足したときにそちらが土台になる
（同梱の `Default-Midnight` は `Base=assets:Default` と書いてある）。
同梱スキンを編集して「名前を付けて保存」したときも、`Base` には
`assets:<名前>` が書き出される。
素材のファイル名は `layout.ini` の中で、その素材を使う表示部品のセクションに
`Img` で始まるキーとして書く（背景なら `[Screen] ImgBack`、バナーなら
`[Banner] ImgBanner`、鍵盤なら `[Keyboard] ImgKeyboard0..2`）。
書かなければ既定の名前（`back.bmp` など）になる。

同梱しているスキンは 6 つ。

| スキン | 宣言サイズ | 中身 |
|---|---|---|
| `Default` | 640x480（横） | 旧 mxv と同じレイアウト。**デスクトップの既定** |
| `Default-Midnight` | 継承（横） | `Base=assets:Default` で配色だけ変えた例（2 ファイルのみ） |
| `Default-Portrait` | 480x640（縦） | `Default` を土台に縦長へ組み替えたもの。デスクトップで縦横切り替えを ON にしたときの縦画面用（デバッグ用） |
| `Default-Landscape` | 720x400（横） | `Default` を土台にファイラーを右へ置いたもの。同じく横画面用（デバッグ用） |
| `Phone` | 480x720（縦） | 縦長の画面向け。**モバイルの縦画面の既定**（切り替え OFF のときの既定でもある） |
| `Phone-Landscape` | 720x480（横） | `Phone` を土台に、ファイラーを右へ置いた横長版。**モバイルの横画面の既定** |

既定の組み合わせはプラットフォームで違う（`settings.cpp` の `kDefaultSkin*`）。
デスクトップは `Default`（切り替え ON なら `Default-Portrait` / `Default-Landscape`）、
モバイルは `Phone` / `Phone-Landscape`（切り替え OFF なら `Phone`）。
それぞれのもう一方はデバッグ用に同梱している。
`mxv2.ini` に書かれたスキンが見つからないときは、起動時の警告を出したうえで
この既定のスキンで表示する（ini は書き換えない。スキンを置き直せば次の起動で
戻る）。

切り替えは設定ウィンドウ (F1) の「スキン」か、起動時の `-skin <指定>`。

### 画面の向きでスキンを切り替える

端末を回したときに、縦画面用と横画面用で別のスキンを使える。**Android では
既定で有効**、デスクトップでは既定で無効（`-orient 1` で有効にできるが、
向きは常に「横」とみなす。窓を自由に変形できるので、縦横比で決めると
変形のたびにスキンが入れ替わってしまうため）。

有効なときは、設定ウィンドウの「スキン」に縦画面用・横画面用の 2 つと、
切り替えかたが出る。スキンの名前には向きの印（`▯` 縦 / `▭` 横）が付き、
そのスロットに合う向きのものが上へまとまる。合わないほうも選べる
（余白が出るだけ）。

| 切り替えかた | 動き |
|---|---|
| 縦画面のみ | 端末を縦で固定する（上下反転はする） |
| 横画面のみ | 端末を横で固定する（左右どちら向きでもよい） |
| 起動時の方向で切り替える | 起動した向きでスキンを決め、以後その向きで固定する |
| 常に切り替える（既定） | 向きが変わるたびにスキンを取り替える |

切り替えかたを変えたときは、**設定ウィンドウを閉じてから**効く。

設定は `mxv2.ini` の `[Screen]` に `SkinPortrait` / `SkinLandscape` /
`Orientation` として残る。**機能が無効なときの `Skin` とは別**なので、
`-orient 0` で起動すれば今までどおりの 1 つのスキンに戻る。
`-skin` を付けて起動したときは、名指しされたスキンを使うために自動で無効になる。

### 画面の 2 分割とウィンドウの伸縮

`[Screen] Width` / `Height` は**宣言サイズ**で、部品の座標も配色もこの大きさを
前提に書く。ウィンドウはそれとは無関係に自由に変えられ、**縦横比が宣言サイズと
違うぶんはファイラーが伸び縮みして吸収する**（行数がその場で増減する）。

そのために、スキンは画面を 2 つに分ける。

| キー | 意味 |
|---|---|
| `[Screen] FilerSide` | ファイラーを置く辺。`Bottom` / `Top` / `Left` / `Right` |
| `[Screen] FilerExtent` | その辺からファイラー側の矩形が何ピクセルあるか（宣言サイズでの値） |

**伸び縮みするのはファイラー側だけ**で、もう一方（鍵盤・ステータス・バナー・
曲名・操作ボタン）の厚みは宣言サイズのまま変わらない。上や左に置いた場合は
その一群がまとめて反対側へ寄るので、**部品の座標は「ファイラー以外側の矩形の
左上」からの相対**として扱われる（下・右に置くなら画面の左上と同じなので、
今までどおりの絶対座標になる）。

伸ばせる上限は `ImgBack` の絵の大きさ。**背景ビットマップを宣言サイズより
大きく作っておくと、その大きさまでファイラーが伸びる。** 同じ大きさなら
伸びず、あふれたぶんは今までどおり余白（レターボックス）になる。
`[配色設定]` で「背景画像を使う」を切っていれば上限は無い。
縮む方向へは宣言サイズで止まり、余ったぶんはやはり余白になる。

同梱スキンの背景は宣言サイズより大きく描いてある。

| スキン | 宣言サイズ | `back.bmp` | 伸び代 |
|---|---|---|---|
| `Default` | 640x480 | 640x640 | 縦 160px |
| `Phone` | 480x720 | 480x1024 | 縦 304px |

ファイラーとスクロールバーの位置は、この分割から決まる。

| キー | 意味 |
|---|---|
| `[FileList] Margin` | ファイラー側の矩形からの内側マージン（左,上,右,下） |
| `[ScrollBar] Width` | 上のマージンで残った矩形のうち、右から何ピクセルをスクロールバーに使うか |
| `[ScrollBar] HitWidth` | スクロールバーの当たり判定の幅（`Width` 以上。左へ広げると、細いバーでも指で掴める） |

**行数と曲名の幅は書かない。** 行数は「一覧の高さ ÷ `ItemHeight`」の切り捨て、
曲名の幅は「一覧の幅 − `TitleX`」で決まる。
スクロールバーの上矢印は上端、下矢印は下端に貼り付き、溝 (`SrcBar`) は
残りの高さぶん**上から繰り返して敷かれる**（素材より長ければ繰り返し、
短ければ途中で切る）。継ぎ目が目立つかどうかは素材側の作りしだい。

音量バーも同じ分け方で、`[VolumeBar]` の `SrcBarLeft` が `Rect` の左端、
`SrcBarRight` が右端に貼り付き、中央 `SrcBar` が残りの幅ぶん**左から繰り返して**
敷かれる（こちらは横方向）。つまみ `SrcThumb` は音量に応じて `Rect` の中を
左右に動く。同梱素材は左から つまみ / 左端 / 右端 / 中央 の順に並べてあり、
前の 3 つは同じ大きさにしてある。

プログレスバーも同じで、つまみが無いだけ（`[ProgressBar]` の `SrcBarLeft` /
`SrcBarRight` / `SrcBar`）。矩形は**上段（未再生）**の位置で、下段（再生済み）は
同じ矩形をその高さぶん下へずらした位置にある。再生位置より左は下段、右は上段から
取る。同梱素材は左から 左端 / 右端 / 中央 の順。

ウィンドウの大きさは `[Position] Save` が有効なら次回起動時に戻る。
表示倍率 (`Zoom`) はそのまま「拡大率」で、変えるとウィンドウが
「キャンバス × 倍率」の大きさに揃え直される。

### 素材ビットマップの約束事

素材は旧 mxv から引き継いだ流儀で、**単なる絵ではなくパレット番号に意味を持たせた
データ**になっている。差し替えるときは以下に従うこと。`back.bmp` 以外を
「24bpp で保存し直す」ことはできない。

#### 背景に対する乗算合成（ゲイン）

多くの素材は背景へ**乗算**で合成される。このときパレットの各成分は色ではなく
**背景に対するゲイン**として働く。配色の `BlackBright` / `WhiteBright` /
`KeyBright` / `BitmapBright` も同じ尺度の値。

| 値 | 結果 |
|---|---|
| 0 | 黒 |
| 1〜99 | 背景 × 値/100（暗くする） |
| **100** | **素通し（背景そのまま）** |
| 101〜 | 背景 + (255−背景) × (値−100)/100（明るくする） |
| 200 | 白 |

パレット番号 **0 は透明**（背景がそのまま出る）。

#### 各ファイル

| ファイル | 色深度 | 使う番号 | 中身 |
|---|---|---|---|
| `back.bmp` | 8/24 どちらでも | 任意 | 普通の絵。パレットも番号も特別扱いしない |
| `banner.bmp` | 8bpp | 49〜148 | **番号がそのまま濃度**（`パレット[i] == (i,i,i)` の恒等グレー）。100 が素通し |
| `minifont.bmp` | 8bpp | 0, 1 | 2 値ステンシル。0=透明、1 に文字色が入る。**ファイルのパレットは使われない**。80 個のグリフを **16 列 x 5 行**に並べたグリフ表で、**1 文字の大きさは画像の大きさ ÷ この並び**（Default は 80x35 なので 5x7）。並びは 0x00〜0x3F が ASCII 0x20〜0x5F の順（空白・記号・数字・大文字。小文字は大文字と同じグリフ）、0x40〜0x49 が制御コード 0x10〜0x19 に割り当てた記号、0x4A〜0x4F が `` ` `` `~` DEL `{` `\|` `}`。0x80 以上の文字は 0 番（空白）になる。対応表は `drawscreen.cpp` の `kMiniGlyphIndex`。画面での送り幅と行の高さは `layout.ini` の `[MiniFont] Width` / `Height` |
| `kb0.bmp` | 8bpp | 1, 2 | 鍵盤の下地。1=黒鍵側、2=白鍵側。配色のゲインが入る。**ファイルのパレットは使われない** |
| `kb1.bmp` / `kb2.bmp` | 8bpp | 0x11, 0x12+n | 鍵。0x11=影、0x12+n=n 番目の音(n=0..11)。**この 12 個のパレットが 12 音の実際の配色になる**。kb1=白鍵側、kb2=黒鍵側 |
| `levelmeter.bmp` | 8bpp | 0, 32〜95 | 番号 = セル番号 + 32。パレット **32〜95 が点灯色、96〜159 が消灯色**（96〜159 は画素には現れない）。ここだけ実色がそのまま出る |
| `playkey.bmp` | 8bpp | 0,1,2,6,7〜11 | 操作ボタン。下記参照 |
| `progressbar.bmp` | 8bpp | 1,2,5 | ゲインのグレー。上段=未再生、下段=再生済み。左から バー左端 / バー右端 / バー中央（残り全部）。`[ProgressBar] SrcBarLeft` / `SrcBarRight` / `SrcBar` で上段の位置を指定（下段は同じ矩形をその高さぶん下） |
| `volbar.bmp` | 8bpp | 1,2,5,6 | ゲインのグレー。左から つまみ / バー左端 / バー右端 / バー中央（残り全部）。`[VolumeBar] SrcThumb` / `SrcBarLeft` / `SrcBarRight` / `SrcBar` で位置を指定 |
| `scrollbar.bmp` | 8bpp | 1,2,3,5 | ゲインのグレー。上から つまみ / 上矢印(押下) / 下矢印(押下) / 溝 |

`levelmeter.bmp` の消灯色は Default では点灯色を 63/255（≒25%）に落としたもの。
`progressbar` / `volbar` / `scrollbar` の番号は「部品の種類」を表す記号で、
濃度ではない（Default では 25=暗い縁、50=溝、100=素通し、150/200=ハイライト）。

`playkey.bmp` のパレット番号は `layout.ini` の `[PlayKey] Pal*` で指定する。
番号のうち `PalKey` には配色の `KeyBright` が入り、LED の 4 つ
（`PalPlayLed` / `PalPauseLed` / `PalContLed` / `PalRepeatLed`）は状態に応じて
`PalGreen` / `PalRed` / `PalDark` のパレットが**コピーされる**。
つまり `PalGreen` / `PalRed` は**画素としては使わず、色を置いておくためだけの
番号**。Default では番号 11 が余っている（使っていない SHUFFLE キーの LED）。

#### 8bpp を外せない理由

背景と一発で合成するブリッタ (`BmpCopyComposite`) がパレット番号を直接見るため、
`minifont` / `levelmeter` / `playkey` / `progressbar` / `volbar` / `scrollbar` は
8bpp 以外を受け付けない（読み込みには成功するが描画されない）。
`banner.bmp` と `kb0.bmp` は 24bpp でも描画は通るが、前者は番号＝濃度、
後者はパレットの書き換えが前提なので 8bpp のままにしておくこと。
差し替えが完全に自由なのは `back.bmp` だけで、これは 24bpp のほうが
減色されないぶん綺麗になる。
