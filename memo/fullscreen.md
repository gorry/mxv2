mxv2 のスキンをフルスクリーン対応にする方法を考えます。
デスクトップのウィンドウスタイルではスキン側で指定するサイズでよいが、モバイルでは画面全体に表示することが望ましいため、どこかを伸縮させて合わせる必要があります。

## 基本的な方法

- ファイラー部分を伸縮させて、画面サイズに合わせます。
- 画面を2分割し、「どちらかをファイラー、もう片方にファイラー以外」を配置するルールとします。
  - 「画面サイズが横480x縦720ピクセル、上470ピクセルがファイラー以外、下250ピクセルがファイラー」と定義したスキンを、横1080x縦1920ピクセルの画面に配置する場合で考えます。
    - 下側がファイラーということは、横は480ピクセルで固定、縦方向を伸縮するということになります。
    - 横1080x縦1920ピクセルの画面に横480ピクセルの矩形をマッチさせる場合、縦は約853ピクセルとなります。
    - 縦853ピクセルのうち、上470ピクセルがファイラー以外側の矩形の高さなので、ファイラー側の矩形の高さは下383ピクセルとなります。
    - 高さ383ピクセルとなったファイラー側矩形に描画できるアイテムの行数を求め、スクロールバーを描画します。
  - 描画された横480x縦853ピクセルのバッファを、横1080x縦1920ピクセルの画面にアスペクト比を保ったまま拡大転送し、文字などを描画して、画面が完成します。

## スキン側（layout.ini）の定義の変更

- スキンに「ファイラーを上下左右どちらに置くか」と「ファイラーとそれ以外の境界はどこか？」の定義を追加します。これにより「ファイラー側の矩形」が定義されます。
- 「ファイラーの描画位置となる矩形」を「XYWH」から「ファイラー側の矩形からの、内側へのマージン量」に置き換えます。
- 「スクロールバーの描画位置となる矩形」を「XYWH」から「「ファイラーの描画位置となる矩形」の右側のピクセル幅」に置き換えます。
- 「ファイラーの行数」は、「ファイラーの描画位置となる矩形」と「1行の高さ」から算出できるため、不要となります。
- 「ファイラーの曲名幅」は、「曲名開始X」と「ファイラーの描画位置となる矩形」と「スクロールバーの描画位置となる矩形」から算出できるため、不要となります。

## 描画の変更

- 現在の背景ビットマップは、「左上を原点に、画面サイズと同じビットマップ」を描画する仕様ですが、ファイラーの伸縮に備えて「画面サイズを超えるビットマップ」を用意するようにします。例えば上記の「横480x縦720ピクセルの画面サイズ」であれば、横480x縦853ピクセルの背景ビットマップを用意しておくようにします。
- 背景ビットマップの描画のオリジンを「ファイラー以外側の矩形」にします。下へ伸縮するのであれば画面左上のままですが、上へ伸縮するのであれば画面左下、左右へ伸縮するのであればそれぞれ「画面左上・画面右上」がオリジンとなります。
- スクロールバーの伸縮は、「素材内: 溝」をリピート描画することで行います。例えば高さ100ピクセルの溝の定義に対して200ピクセルの溝を描画する場合は、100ピクセル分を2回と半分リピートします。逆に、高さ250ピクセルの溝の定義に対して200ピクセルの溝を描画する場合は、上から200ピクセル分だけを描画します。
- デスクトップの場合、ウィンドウサイズを変更することで、ファイラーの行数をリアルタイムに変化させることができます。**ウィンドウは自由に変形できるものとし、キャンバスの高さ（＝ファイラーの行数）がウィンドウに追従します**（OS 側でリサイズを拘束することはしません）。
  - ただし、ファイラーを縮める方向に変化させる場合は、画面サイズで定義されるアスペクト比を維持します。例えばファイラーを下に置く場合、画面サイズが横480x縦720ピクセルで定義されているならば、横480に対して縦比率を720より小さくすることはできません。横方向を縮めて（左右に余白を作って）縦比率720以上を維持することになります。
  - また、ファイラーを伸ばす方向に変化させる場合は、制限は「背景ビットマップの高さ」となります。例えばファイラーを下に置く場合、画面サイズが横480x縦720ピクセルで定義されていて、背景ビットマップが横480x縦853ピクセルならば、横480に対して縦比率を853より大きくすることはできません。
    - 画面サイズより背景ビットマップが小さい場合、この計算における背景ビットマップのサイズは、画面サイズ以下にはしないようにします。
    - 「背景ビットマップを使わない」設定なら、伸ばす方向に制限はなくなります。
  - 上下どちらの制限に当たった場合も、**あふれたぶんは今までどおり余白（レターボックス）**になります。つまり制限は「キャンバスの大きさを決めるときの上下限」であって、ウィンドウの大きさを縛るものではありません。

## 決定事項（2026-09-09）

| 論点 | 決定 |
|---|---|
| 画面がスキンの定義より横長で、伸ばす余地がマイナスになるとき | **今までどおりレターボックス**。定義の比（例 480:720）を保ったまま高さ基準で拡大し、左右に余白を置く。「向きでスキンを切り替える」は将来入れるが、今回はやらない |
| 新しいキーを持たない既存スキン | **旧キーから推定した値で書き換える**（同梱の 2 スキンだけ。まだ公開していないので、ユーザーが作ったスキンは存在しない）。旧キーの後方互換は用意しない |
| スクロールバーの位置指定 | **描画の幅と当たり判定の幅を別のキーで持つ**（Phone の「見た目より広い当たり判定」を残すため） |
| デスクトップのウィンドウと表示倍率 | **ウィンドウは自由にリサイズでき、表示倍率 (Zoom) は拡大率**。キャンバスの高さはウィンドウに追従する |

### 決定から確定する算出式

ファイラーを上下に置く場合（左右に置く場合は縦横を読み替える）:

```
canvasH = round(outH * declaredW / outW)          // 幅を基準にする
canvasH = clamp(canvasH, declaredH, maxStretchH)  // 下限＝定義の高さ、上限＝背景ビットマップの高さ
                                                  // （背景を使わない設定なら上限なし）
```

そのうえで、**描画は今までどおり縦横同率の拡大＋中央寄せ**とする。こうすると
「伸び代がマイナス＝ `declaredH` に張り付く＝左右に余白」が自動的に決定どおりになる。
また、拡大を非同率にしないことで、マウス座標の逆変換 (`Screen::WindowToCanvas`) と
sharp-bilinear の中間テクスチャ (`Screen::EnsurePreTexture`) をそのまま使える。

検算:

- 480x720 のスキンを 1080x1920 へ … `canvasH = 853`（背景ビットマップが 853 以上ある場合）。
- 480x720 のスキンを 1920x1080 へ … `canvasH = 270` → `720` にクランプ。拡大率 1.5、左右に余白。

## 決めたこと（未決事項の答え。2026-09-09 に実装まで済ませた）

### 分割の定義

- 境界は **`[Screen] FilerExtent`（ファイラー側の辺からの距離 px）** で書く。
  上下左右どの配置でも意味が同じで、伸縮しても値が変わらない。
  辺は **`[Screen] FilerSide`（`Bottom` / `Top` / `Left` / `Right`）**。
- 境界線は**ファイラー側**に属する。`FilerExtent` がそのままファイラー側の
  矩形の厚みになり、ファイラー以外側は「宣言サイズ − FilerExtent」。
- 左右に置く場合は縦横を読み替えるだけ。伸びるのは横で、行数は変わらず
  1 行が長くなる（横長の画面で曲名を長く出すための配置）。
- **ファイラー以外側の部品の座標は、その矩形の原点からの相対**とする。
  下・右に置くなら原点は画面の左上なので、今までの絶対座標と同じ。
  上・左に置いたときだけ、`[Keyboard]` `[Status]` `[Banner]` `[PlayKey]`
  `[Title]` `[ProgressBar]` `[VolumeBar]` がまとめてずれる。
- 境界をまたぐ部品は**禁止しない**（描けてしまうが、伸ばすと重なる）。

### 端数と限界

- 端数は**四捨五入**し、残る 1px 以下はレターボックスで吸収する。
- 伸ばせる上限は `ImgBack` の絵の大きさ（宣言サイズより小さければ宣言サイズ）。
  「背景画像を使わない」設定なら上限なし。ただし**宣言サイズの 8 倍**で
  頭打ちにする（`Skin::kMaxCanvasStretch`。窓を極端に細長くしたときに
  途方もない大きさのバッファを作らないための保険）。
- 背景が足りない領域は今までどおり黒のままで、その上に配色の背景色が
  `BitmapBright` / `ColorBright` で乗る（`CompositeBack` の順番は変えていない）。
- 同梱スキンの背景ビットマップは**ユーザーが描き直した**（2026-09-09）。
  Default は 640x480 → **640x640**、Phone は 480x720 → **480x1024**。
  伸び代はそれぞれ 160px / 304px で、Phone を Pixel 7a 相当の縦横比
  （480x958）に伸ばすとレターボックスは消える。上限を超えるところまで
  窓を伸ばすと、あふれたぶんは今までどおり余白になる（実測: Default を
  640x800 にすると上下 80px ずつ、Phone を 480x1200 にすると上下 88px ずつ）。

### ファイラーとスクロールバー

- 行数は **`floor(一覧の高さ ÷ ItemHeight)`**。既存の値と一致する
  （Default 110/10=11・110/13=8、Phone 250/16=15・250/24=10）。
- 曲名の幅は **`一覧の幅 − TitleX`**。`TitleWidth` は廃止した。
  **Default の大きい文字は挙動が変わる**（手書きの 624 → 算出値 458）。
  624 は一覧の幅 620 を超えていて、曲名が長いとスクロールバーの上まで
  字が出ていた（文字は出力解像度のレイヤーに描くので、キャンバス側の
  スクロールバーより手前に出る）。算出値にしたことでその食い込みは消え、
  代わりに**横スクロールが始まるのが早くなる**。これは許容する。
- `BaseNameWidth` は残す（一覧の幅からは決まらない）。
- 新しいキーは「小,大」の 2 つ組にしない。`[FileList] Margin` は
  「左,上,右,下」の 4 つ組、`[ScrollBar] Width` / `HitWidth` は 1 つの値。
- スクロールバーの伸縮: **矢印は伸ばさず上端・下端に貼り付け**、
  **つまみは素材の大きさのまま**、**溝は上端から繰り返して敷く**
  （素材より長ければ繰り返し、短ければ途中で切る）。継ぎ目が目立つかは
  素材側の責任。同梱の 2 つはどちらも溝が 1 行の繰り返しなので継ぎ目は出ない。
- つまみの移動量は**描いた溝の高さ**から出す（`Skin::scrollBarMovement()` を
  `scrollGrooveH - scrollSrcThumb.h` に変えた）。ドラッグの計算もここを見る。
- スクロールバーの位置は `[FileList] Margin` で残った矩形の右端から
  `[ScrollBar] Width` ぶん。**描画の矩形と一覧の矩形は必ず隣り合う**ので、
  今まであった「重なった列には描かない」帯分割は要らなくなった（消した）。
  指で掴みやすくするための広い当たり判定は `[ScrollBar] HitWidth` が受け持ち、
  そちらは一覧に食い込むが描かない。

### モバイル

- 「画面全体」は **SDL のウィンドウいっぱい**。ステータスバーなどは
  SDL が渡してくる大きさの時点で既に除かれている。
- 回転したときは当面この文書の決定（レターボックス）に落ちる。
  `android.md` の保留事項「画面の向きとスキン」に着手するときに再訪する。

### デスクトップ

- リサイズのデバウンスは、**イベントで印だけ立てて、フレームの頭で 1 回だけ
  作り直す**ことで済ませた（`SyncCanvasToWindow`）。ドラッグ中に何十回
  イベントが来ても、作り直しは 1 フレームに 1 回。
- 行数が変わったときのカーソルとスクロール位置は
  `Filer::SetViewMetrics` が今までどおり面倒を見る（先頭の項目を保って
  測り直し、カーソルが画面外なら送り直す）。
- **ウィンドウの大きさを `[Position]` に覚える**ようにした。位置だけ戻して
  大きさを戻さないと、次の起動で形（＝ファイラーの行数）が変わってしまうため。
  戻すのは伸ばす方向だけで、「宣言サイズ × 表示倍率」を下限にする
  （表示倍率が 100% を割らないように）。

## 実装（2026-09-09）

### layout.ini の変更

| 旧 | 新 |
|---|---|
| — | `[Screen] FilerSide` = `Bottom` / `Top` / `Left` / `Right` |
| — | `[Screen] FilerExtent` = ファイラー側の矩形の厚み (px) |
| `[FileList] Rect` | `[FileList] Margin` = 左,上,右,下 |
| `[FileList] Rows` | 廃止（`floor(高さ ÷ ItemHeight)`） |
| `[FileList] TitleWidth` | 廃止（`一覧の幅 − TitleX`） |
| `[ScrollBar] Rect` | `[ScrollBar] Width` と `[ScrollBar] HitWidth` |
| `[ScrollBar] PosUpArrow` / `PosBar` / `PosDownArrow` | 廃止（上端・下端に貼り付き、間が溝） |

旧キーの後方互換は用意していない。同梱の 2 スキンは書き換え済みで、
**旧レイアウトと同じ位置・同じ行数になることをテストで突き合わせてある**
（`SkinEditor.Tests/SkinPlacementTests.cs`）。

Phone のスクロールバーは、素材の幅 24 のうち左 12px が透明
（旧レイアウトで当たり判定に使っていた名残）だったので、`Src*` を
絵のある右 12px を指すように直し、`Width=12` / `HitWidth=24` にした。
素材そのものは変えていない。

### 本体 (C++)

- `Skin` に `PlacedFor(canvasW, canvasH)` と `CanvasSizeFor(outW, outH, limit)` を
  足した。前者は**導出値を埋めたコピー**を返し、ファイラー以外側の部品の
  座標にはその矩形の原点を足す。
- `DrawScreen` は `layout_`（そのコピー）を見て描く。`skin_` を直に見るのは
  `skin()` だけ。`Resize(canvasW, canvasH)` でバッファを作り直す。
- `Screen::SetCanvasSize` を足した（`Resize` から窓のリサイズを外したもの）。
  窓に追いかけてキャンバスを変えるときはこちら。
- `main.cpp` の `SyncCanvasToWindow` が、フレームの頭で
  「出力の大きさ → キャンバスの大きさ → 画面・文字レイヤー・DrawScreen・
  Filer」の順に合わせ直す。

### スキンエディタ

- `SkinLayout.PlacedFor` を本体と 1:1 で移植し、`SkinDocument.Placed` を
  プレビューと枠が見る。編集値の表示は `Effective`（layout.ini に書くキー
  そのもの）のまま。
- `FieldKind.Enum` を足した（`[Screen] FilerSide` 用のコンボボックス）。
  数値スピンしか無かったので、列挙値の受け皿を新設した。
- `[FileList] Margin` と `[ScrollBar] Width` / `HitWidth` はドラッグ非対応。
  掴んで動かす形の値ではないので、枠を出すだけにした。
