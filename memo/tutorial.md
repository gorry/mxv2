初回起動時のチュートリアルを追加します。

## 方針

- 用意したシナリオに沿って進む形（本体の動作に割り込む）。ダイアログを初めて
  開いたときに出す形は採らない。
- 対象は「MXDRV も mxv も知らない人」。MDX の説明はしないが、
  「曲を選ぶ → 鳴る → 画面が動く」までを最短で体験させる。
- 1 ステップ 1 つのこと。全部で 10 ステップ前後、通しで 2〜3 分。
- いつでも [終了する] で抜けられる。抜けたあとは二度と出ない
  （もう一度見たければ [設定] の [動作] のチェックボックスから）。
- 説明の文面はカタログ (`message.ini`) に置き、デスクトップ／モバイル
  （`Screen::TouchPreferred()` と同じ判定）で操作の呼び方を変える。
  キー名はデスクトップだけ、はじく操作はモバイルだけ、といった出し分け。

## 画面の作り

- 本体の上に半透明の幕を掛け、**注目する部品だけ幕を抜いて明るく残す**
  （スポットライト）。部品の矩形は `layout.ini` から取れる（曲名欄、
  操作ボタン、鍵盤、ファイラーなど）ので、スキンが違っても位置が合う。
- 幕の上に小さな吹き出し（ImGui のウィンドウ）。中身は
  「見出し 1 行」「説明 2〜3 行」「[次へ] [終了する]」。位置はスポットの
  邪魔にならない側（上半分を照らすなら下、下半分なら上）。
- 「やってみる」ステップは、**その操作が実際に起きたら自動で次へ進む**
  （[次へ] を押しても進める）。それ以外の操作は幕が吸い取る
  （誤操作で先へ飛ばないように）。ESC は [終了する] と同じ（確認 1 回）。
- 画面が回転したりスキンが替わったりしたら、幕と吹き出しを置き直す
  （ダイアログと同じ `placeCond()` の仕組み）。

## シナリオ

番号は順番。「▶ やってみる」は操作待ち、それ以外は [次へ] で進む。

### 1. ようこそ

- スポット: なし（画面全体を薄く暗くする）
- 「mxv2 へようこそ。X68000 の音楽データ (MDX) を鳴らして、その様子を
  眺めるアプリです。使い方を 2 分で案内します。「終了する」でチュートリアルを
  終了します。」
- [はじめる] [終了する]。ここで終了したら以後は出ない。

### 2. ファイラー

- スポット: ファイラー全体
- 「下の一覧がファイラーです。フォルダと曲が並びます。いまは同梱の曲
  (Assets>) を開いています。」
- 「▶ やってみる: `ArctanX` を開いてください。」
  - デスクトップ: 「上下キーで選んで ENTER、またはダブルクリック」
  - モバイル: 「タップして選び、右へはじく（またはダブルタップ）」
- 完了条件: カレントフォルダが `assets:ArctanX` になった。

### 3. 曲を鳴らす

- スポット: ファイラー
- 「曲の行を開くと演奏が始まります。」
- 「▶ やってみる: 好きな曲を開いてください。」
- 完了条件: 演奏が始まった（`Player` が playing になった）。
- ~~補足（自動で次へ進んだ直後に 1 行）~~ → 0.5 秒の「間」で見せるので不要
  （2026-09-13 に `Text3Done` を廃止）。

### 4. 鍵盤とステータス

- スポット: 鍵盤 9 段 + ステータス欄
- 「鍵盤は 8 つの FM 音源チャンネルと、一番下の PCM です。右の欄は
  各チャンネルの音量や音色の状態です。」
- 「▶ やってみる: 好きな段の鍵盤を押してください。
  そのチャンネルだけ音が止まります。もう一度でもとに戻ります。」
  - デスクトップの補足: 「キーの 1〜8 でも同じ」
- 完了条件: 一度どれかのチャンネルを OFF にしたあと、すべてのチャンネルを ON に
  戻した（2026-09-13 に変更。以前は「どれかが切り替わった」）。
- 次へ進む前に、マスクを全部解除しておく（音が欠けたまま先へ行かない）。

### 5. 操作ボタン

- スポット: PREV / STOP / PLAY / FAST / PAUSE / NEXT
- 「演奏の操作です。左から 前の曲・停止・再生・早送り・一時停止・次の曲。」
- 「▶ やってみる: 一時停止して、もう一度押して再開してください。」
  - デスクトップの補足: 「SPACE でも同じ」
- 完了条件: pause → resume の 1 往復。

### 6. CONT / REPEAT と音量

- スポット: CONT / REPEAT / 音量バー / プログレスバー
- 「CONT を点けると、曲が終わったら次の曲へ進みます。REPEAT は同じ曲を
  繰り返します。音量バーは曲ごとの音量、プログレスバーで演奏位置を
  動かせます。」
- 「▶ やってみる: CONT を点けてください。」（[次へ] でも可）
- 完了条件: CONT が ON になった。
- 補足: 「設定は次回の起動にも残ります。」

### 7. メニュー

- スポット: バナー（MXV ロゴ）
- 「ロゴを押すとメニューが出ます。設定や配色、曲の置き場所の

  - デスクトップの補足: 「右クリックでも出ます」
- 「▶ やってみる: メニューを開いて、[mxv2 の設定] ダイアログを開いてください。」
- 完了条件: [mxv2 の設定] ダイアログが開いた。

  - デスクトップ: 「ESC キーでも閉じられます」

  - モバイル: 「左へはじく」

## いつ出すか

- `mxv2.ini` に `[Tutorial] Done=1` が**無い**とき、起動直後の
  [起動時の警告] を閉じたあと（警告が無ければ最初のフレーム）に始める。
- コマンドラインで曲を指定して起動したとき（`-quit` を含む）は出さない
  （その人はもう使い方を知っている）。`Done` も書かない。
- `-tutorial` で強制的に出す（`Done` は無視、終わっても書き換えない。
  デバッグ用）。
- ~~メニューに [チュートリアル…] を足す~~ → **2026-09-13 に廃止**。代わりに
  [mxv2 の設定] の一番下に [動作] グループを作り、「次回起動時にチュートリアルを
  表示する」チェックボックスを置く。`[Tutorial] Done` の裏返しで、入れると
  次の起動で出る（見終えるとまた外れる）。
- スキップ／最後まで見た、のどちらでも `Done=1` を書く。
- 始めるときにファイラーを `assets:` の根へ移し、CONT / REPEAT を消す
  （2026-09-13、ユーザーの指示。ステップ 2 の「ArctanX を開く」がその場に
  ある状態から始めるため）。

## 本体との取り合い

- 幕が出ている間、操作待ちステップで**期待している操作だけ**を通し、
  それ以外のマウス・キー・タッチは幕で止める。ただし ESC（スキップ）と、
  ウィンドウの × は通す。Android の戻るキーはスキップ扱い。
- 判定は本体の状態を見る（ファイラーのカレント、Player の状態、
  マスクのビット、CONT のフラグ、メニューの開閉）。イベントを横取り
  して判定しない（本体が動いた結果だけを見る）。
- 演奏中に先へ進んでも音は止めない。最後まで見終えても曲は鳴ったまま。
- ステップ 4 で切り替えたマスクは、次へ進む前に全解除する。
- 起動直後の曲名欄「Welcome to the MXDRV world. Get ready!」はそのまま。

## 積み残し・決めていないこと

- 吹き出しの文面はカタログ `[Tutorial]` に置く（ja-JP / en）。
- Phone スキン（縦長）では鍵盤 9 段がファイラーより上にあるので、
  吹き出しは常に下側でよいか要確認。
- スポットの矩形は `DrawScreen` の layout から取るが、鍵盤の「9 段まとめて」
  と操作ボタン「6 個まとめて」は外接矩形を足す必要がある。
- モバイルのダブルタップ判定（500ms / 32px）で「開く」が誤爆しないか、
  ステップ 2〜3 で様子を見る。

## 実装（2026-09-12）

- `src/tutorial.h/.cpp` が新規。`Tutorial` クラス 1 つ。本体の状態は
  `Tutorial::State`（ファイラーの場所・選択画面か・演奏中か・一時停止か・
  マスク・CONT・メニューの開閉・指操作か）に main が毎フレーム詰める。
- 幕は `ImGui::GetBackgroundDrawList()` にスポットの外側 4 枚の矩形として
  描く（穴の縁に黄色の線）。スポットの矩形は `DrawScreen::layout()` から
  取り、`Screen::CanvasRect()` で実ピクセルへ写す。吹き出しは題名なしの
  ImGui ウィンドウ（幅 400 x 倍率、高さは中身任せ）。スポットが画面の
  上半分なら下、下半分なら上に出し、入らなければ画面の下端に寄せる。
- 入力は main の `SDL_PollEvent` ループで `Tutorial::AllowsMouse` /
  `AllowsKey` を通す。押した場所を許可したら離すまで通す（MouseInput の
  押下を宙に浮かせない）。ホイールはファイラーの段だけ。ESC / 戻るキーは
  `RequestSkip()`（吹き出しの中で確認）。ImGui が掴む入力（吹き出しの
  ボタン、右クリックメニュー）は従来どおり ImGui が先に取る。
- 吹き出しのボタンを押すと ImGui のフォーカスがそこに付いて
  `WantCaptureKeyboard` が立つので、他のポップアップが無ければ毎フレーム
  `SetWindowFocus(NULL)` で外す。
- 鍵盤の段を抜けるとき（[次へ] でもスキップでも）は `TakeMaskReset()` で
  main に全チャンネルのマスク解除を頼む。
- ステップ 8 は選択画面に着いたら文面を `Text8After*` に差し替えて
  [次へ] 待ちにする（`fsReached_`）。
- 文言は `[Tutorial]`（ja-JP / en）。段落はキーを分ける（ini の値は 1 行）:
  `Title<n>` `Text<n>` `Text<n>Desktop|Mobile` `Try<n>` `Try<n>Desktop|Mobile`。
- `[Tutorial] Done` は `Settings::tutorialDone`（`kFieldTutorial`）。
  始めるのは `ui.anyDialogOpen()` が偽になってから（起動時の警告のあと）。
  メニューの [チュートリアル…] は 2026-09-13 に廃止（設定のチェックボックスへ）。
- 積み残しにあった 3 点: Phone スキンでは鍵盤がファイラーより上にあるので
  吹き出しは下に出る（スポットが大きければ下端に寄せる）。鍵盤 9 段と
  操作ボタンは矩形の和で外接矩形を作る（`Rect::unite`）。ダブルタップの
  誤爆は実機で見る。

**文言の決めごと（2026-09-13）**: キー名は「??? キー」、ボタン名は「??? ボタン」と
書く。抜ける操作は「スキップ」でなく「終了する」（確認は「チュートリアルを
終了しますか？」）。

**操作完了後の「間」（2026-09-13、ユーザーの指示）**: 操作待ちが満たされた瞬間に次へ
飛ぶと分かりにくいので、満たしたら 0.5 秒 UI を止め（本体の入力も吹き出しの
ボタンも効かない。ESC も無視）、そのあと次の段へ進む（`Tutorial::holding_` /
`kHoldMs`）。

**シナリオの並び替え（2026-09-13、ユーザーの指示）**: メニューの段は「[mxv2 の設定] を
開く」までにし、続けて設定の段（ダイアログを閉じたら次へ）、そのあと曲の置き場所 →
ブックマーク → おわり。番号は進行順に振り直し、カタログのキーも同じ番号
（7 メニュー / 8 設定 / 9 曲の置き場所 / 10 ブックマーク / 11 おわり）。

**折り返しの禁則（2026-09-13）**: ImGui の TextWrapped は英文向けで「。」「」」が
行頭に来るので、`src/kinsoku.{h,cpp}` の `WrapTextKinsoku` / `TextWrappedKinsoku`
で自前に改行を入れてから渡す（ASCII の語は切らない、日本語は 1 字ずつ、
行頭・行末禁則の字は追い出し）。吹き出し・設定の段の直描き・確認ダイアログの
本文・起動時の警告・注記 (TextNote/TextError) がこれを使う。
