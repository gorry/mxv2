現在、ファイラーのルート（根本）はWindowsのローカルファイルシステムです。この1段上に、「ファイルシステムの選択」を採り入れます。

## ファイルシステムの選択肢

- ブックマーク
  - ブックマークの一覧を出し、選択するとブックマーク先へジャンプする、ジャンプ専用の
    ファイルシステムです。詳細は bookmark.md の「ファイラーの『Bookmarks>』」。
  - 初回起動時から使用可能とします（削除不可）。初期状態では最上部に置きます。
- assetsフォルダ
  - assetsフォルダのルートに`mdx/`フォルダを設置し、その`mdx/`フォルダをルートとします。
  - 初回起動時から使用可能とします。
- ユーザーフォルダ
  - ユーザーフォルダのルートに`mdx/`フォルダを設置し、その`mdx/`フォルダをルートとします。
  - 初回起動時から使用可能とします。
- ローカルファイルシステム
  - 既存のものと同じ。
  - デスクトップでは初回起動時から使用可能とします。
  - モバイルでは状況により異なります。
    - 使用できない環境があります（Androidなど）。この場合は使用不可能とします。
- フォルダマウント
  - OSネイティブの任意のフォルダパスをルートとします。
  - ユーザーが「ファイルシステムの設定」から追加します。初回起動時には存在しません。
  - 場所の指定は、**OSネイティブのパス入力**と、**OSの「フォルダを探す」ダイアログ**で
    行います。ファイラーの「フォルダを開く」ダイアログ（自前でVFSの中を辿るもの）は
    使いません。OSにダイアログが無い環境では、パス入力のみとします。
  - 追加できる数に制限は設けません。同じ場所を二重に追加することははじきます。
  - WindowsのUNCパス（"\\server\share\..."）もそのまま指定できます。この場合は
    外部ファイルシステム扱いとし、「親を1つずつ遡る」処理を行いません。
  - ブックマークと用途が重なりますが、両方あってよいものとします
    （ブックマークは「行き先」、フォルダマウントは「ルート」）。
- 外部ファイルシステム
  - Androidのストレージは、Storage Access Framework (SAF)経由になり、ここに含みます。
    - **アクセス許可が失われても消さない**（2026-09-16）。アプリをアンインストールすると
      OS が永続 URI 権限を捨てるが、mxv2.ini はクラウドバックアップから戻ってくる。
      この状態で起動しても `saf:` の項目とその先を指すブックマークは残し、
      「アクセス許可なし」の印を付けて一覧に出す（`FileSystem::accessible()` が false。
      `available()` と違ってマウントには残る）。
    - 取り直しへの導線は 3 つ: (1) 起動時の警告ダイアログの項目に [許可を取り直す…] が付き、
      その場で OS のピッカーへ。戻ってくると項目が「〜 の許可を取り直しました」に変わる。
      (2) ファイラーでその行（FS 選択）や、その先を指すブックマークを開くと、直に OS の
      ピッカーが出る。取り消したり別のフォルダを選んだときは「ファイルシステムの設定」が
      その行と注記つきで開く。(3)「ファイルシステムの設定」の [許可を取り直す…]。
  - WebやSMB、クラウドファイルシステムなど。
  - 仕様として記述するのみで、現時点ではまだ着手しません。段階的に着手します。

## ファイルシステムの表記

- ファイルシステムを含むフルパスの記述として、以下の接頭辞を用います。
  - **ブックマーク**: "bookmark:"（場所はルートだけ）
  - **assetsフォルダ**: "assets:"
  - **ユーザーフォルダ**: "userdir:"
  - **ローカルファイルシステム**: "localfs:"
  - **フォルダマウント**: "dir:[PATH]"
    - PATHはOSネイティブのフルパス表記とします（Windowsなら"dir:H:\music"）。
    - 同じ種類を複数マウントできるため、接頭辞だけでは行き先が決まりません。
      パスまで見てどのマウントのものかを決めます（`Vfs::Parse` と `Vfs::Resolve` の
      両方。2026-09-16 まで `Resolve` は接頭辞だけで 1 つ目を選んでいて、2 つ目の SAF の
      中を PDX の探索先に指定できなかった）。
  - 外部ファイルシステム
    - **SAF(Android)**: "saf:[URI]"
    - **Web**: "web:[URL]"
    - **SMB**: "smb:[PATH]"
    - クラウド
      - **Googleドライブ**: "gdrive:[PATH]"
      - **OneDrive**: "onedrive:[PATH]"
      - **iCloud**: "icloud:[PATH]"
  - Windowsのファイルシステムは、「1文字のドライブ名+":"」という記述を行います。これを「未知の接頭辞」として扱わないようにするため、「2文字以上の英文字+":"」を接頭辞として扱います。
- 外部からパスを入力された場合（iniファイルから読み込んだ場合も含む）は、正規化を行います。
  - 接頭辞がない場合、ローカルファイルシステムのフルパス表記であるかを調べます。フルパス表記であればローカルファイルシステムのそれとして扱い、そうでなければ相対パスとしてフルパス化してから扱います。
    - 相対パスである場合、「どこからの相対パスであるか」は、文脈によります。
      - layout.ini 内の場合は、layout.iniファイルのあるフォルダからの相対パスとなります。
      - コマンドライン引数内の場合は、プロセスのカレントディレクトリからの相対パスとなります。
      - 「フォルダを開く」ダイアログの場合は、ダイアログ内で開いているフォルダからの相対パスとなります。
  - 未知の接頭辞の場合、エラーとして扱います。
  - フォルダ（ディレクトリ）の区切り文字は、正規化を行います。正規化のルールは、ファイルシステムごとのルールに準じます。例えばWindowsのローカルファイルシステムでは"\"となりますが、それ以外の多くのファイルシステムでは"/"となります。末尾の区切り文字は常に捨て、必要に応じて付加します。
    - 「localfs:」のみの場合の正規化の結果は、「OSのシステムドライブのルート（Windowsなら"%SystemDrive%\"、通常は"C:\"）」とします。
  - 名前の比較の際、大文字/小文字のファイル名判定は、ファイルシステムごとのルールに準じます。例えばWindowsのローカルファイルシステムでは大文字/小文字を無視しますが、それ以外では無視するシステムもしないシステムもあります。
- layout.ini 内の[Skin]:Baseにおいての"assets:"記述はパスではない（スキン名の修飾）のため、ファイルシステムとは関連しません。

## ファイラーの表示

通常の表示は今まで通りです。ルート（ファイルシステムの選択）で以下の表示を行います。

- 「ファイルシステムの設定」ダイアログで並べた順に表示します。
  - **ブックマーク**: "Bookmarks>"。曲名の代わりに「ブックマーク」を表示します。
  - **assetsフォルダ**: "Assets>"。曲名の代わりに「同梱アセット」を表示します。
  - **ユーザーフォルダ**: "UserDir>"。曲名の代わりに「ユーザーフォルダ」を表示します。
  - **ローカルファイルシステム**: "Local>"。曲名の代わりに「ローカルファイルシステム」を表示します。
  - **フォルダマウント**: "DIR>"。曲名の代わりにルートのフルパスを表示します。
  - 外部ファイルシステム
    - **SAF(Android)**: "SAF>"。曲名の代わりにURIを表示します。
    - **Web**: "Web>"。曲名の代わりにURLを表示します。
    - **SMB**: "SMB>"。曲名の代わりにSMBパスを表示します。
    - クラウド
      - **Googleドライブ**: "GDrive>"。曲名の代わりに接続先情報を表示します。
      - **OneDrive**: "OneDrive>"。曲名の代わりに接続先情報を表示します。
      - **iCloud**: "iCloud>"。曲名の代わりに接続先情報を表示します。
- 初期の並び順は、上記の記述順となります。
- 最終項目に"[Setting]"（曲名の代わりに"[ファイルシステムの設定]を開く"）を表示し、そこから「ファイルシステムの設定」ダイアログを表示します。
  - コンテキストメニュー、F3キーにも「ファイルシステムの設定」ダイアログ表示を割り当てます。
- 各ファイルシステムのルートにいる時、最上部の"\   A:\"などとなっている表示を"[FS]   A:\"とし、これを選択するとルート（ファイルシステムの選択）を表示します。
  - 「ファイルシステム」カラーで表示します。
- "\"キーは、各ファイルシステムのルートにジャンプします。"Backspace"キーを各ファイルシステムのルートで押した時は、ルート（ファイルシステムの選択）にジャンプします。
- 配色設定に「ファイルシステム」を追加します。「ファイルシステムの設定」項目はMDXの色を使用します。
- `assets/mdx` フォルダが存在しない状態でassetsフォルダを開いた場合、空のリスト（"[FS]"だけ）を表示します。

## 「ファイルシステムの設定」ダイアログ

ファイラーのルート（ファイルシステムの選択）に表示されるファイルシステムを設定します。
実質的には「mxvにマウントされるファイルシステムの一覧と、その表示順序」を設定することになります。

### 画面構成

- マウントするファイルシステムのリスト
  - ファイルシステム（ファイラーと同様に、ファイルシステム名と諸情報）を表示します。
  - いずれか1つを選択可能です。初期状態では一番上を選択しておきます。
  - 削除不可能なファイルシステムを、色で判別可能にしておきます。
- [上へ]ボタン
  - 選択したファイルシステムをひとつ上へ上げます。上げられない場合はグレーアウトします。
- [下へ]ボタン
  - 選択したファイルシステムをひとつ下へ下げます。下げられない場合はグレーアウトします。
- [追加]ボタン
  - 選択位置へファイルシステムを挿入します。
    - 「ファイルシステム選択」ダイアログを出して、そこから挿入するファイルシステムを選びます。
      - 追加できるファイルシステムは、フォルダマウントと外部ファイルシステムのみになります。
      - まずファイルシステムを選択し、続いて場所を決定し、必要であれば資格情報を入力・取得します。
        - 追加できるファイルシステムが1種類しかない場合は、種類の選択を省略します。
        - フォルダマウントの場所は、パス入力欄と[参照...]（OSの「フォルダを探す」
          ダイアログ）で決めます。
      - 同じファイルシステムを複数追加することはできますが、既存と同じ場所ははじきます。
  - 追加できるファイルシステムがない場合は、グレーアウトします。
- [許可を取り直す…]ボタン（2026-09-16）
  - アクセス許可が失われた SAF のファイルシステムを選んでいるときだけ押せます。
  - 端末の「フォルダを選ぶ」画面を、元のフォルダを初期位置にして開きます（Android 8 以降）。
  - 同じフォルダを選び直すと、そのマウントが読める状態に戻ります（順番も ini も変わらず、
    その先を指すブックマークもそのまま効く）。別のフォルダを選んだときは [追加…] と同じく
    新しいマウントとして足し、元のものは残ります。
- [削除]ボタン
  - 選択したファイルシステムを削除します。
    - 「本当に削除するか」を問い合わせ、了解を得た場合のみ削除します。
  - 削除不可能なファイルシステムを選択している時は、グレーアウトします。
    - 「初回起動時から使用可能」なファイルシステムは、削除不可能とします。
  - 現在カレントになっているファイルシステムを選択しているときは、グレーアウトしません。代わりに、[削除]ボタンを押したときに「カレントは削除できない」旨を表示して戻ります。

## ファイルシステムのリストの保存

mxv2.iniに保存します。

```
[FileSystem]
Count=4
FS1=assets:
FS2=userdir:
FS3=localfs:
FS4=dir:H:\music
```

場所を持つファイルシステム（フォルダマウント、外部ファイルシステム）は、
接頭辞に続けてその場所を書きます。

読み込み時は以下の処理をします。

- 下記が発生した場合、読み込みを完了した後に再保存を行います。
  - 未知のファイルシステムだった場合は、警告を表示して、それを捨てます。
  - Count以上のFS<n>は（暗黙に）捨てます。
  - 削除不可能なファイルシステムが含まれていなかった場合、（暗黙に）それをリストの末尾に足します。
    ただしブックマークは先頭に足します。

## その他

- PDX探索順序を以下のようにします。
  - MDXファイルと同じフォルダ。
  - MDXファイルがあるファイルシステムのルートにある`pdx/`フォルダ。ただし、ローカルファイルシステムの場合はこれをスキップします。
    - このフォルダはファイラーではとくに隠蔽しません。
  - PDX探索先リストに指定したフォルダ（`-pdxpath` → 設定の一覧の並び順）。
    MDXファイルのあるファイルシステム以外も探索に含みます。
  - 探索先リストは設定ダイアログから別ダイアログ [PDX の探索先] を開いて
    管理します（ブックマークの設定と同じ作り）。iniは `[Path] PdxCount` /
    `Pdx<n>`。
- iniファイルに保存する外部ファイルシステムの情報には、認証情報を含んではなりません。
- ファイルシステムを削除したとき、そこを指しているブックマークや「前回終了時のカレント
  フォルダ」はそのまま残します。開こうとした時点で「見つかりません」となり、次回起動時の
  読み込みで（未知の接頭辞として）捨てられます。
- 初回起動時（前回終了時のカレントフォルダが記録されていない時）、assetsフォルダをカレントフォルダとします。
  - 前回終了時のカレントフォルダの記述が「未知の接頭辞」の場合、未記録と同じ扱いとします。
  - 前回終了時のカレントフォルダの記述が「ローカルファイルシステムのパスとして解釈不能」の場合、未記録と同じ扱いとします。
- 起動時に前回終了時のカレントフォルダに移動できない場合は、フォルダを1つずつ遡ります。最終的にはルート（ファイルシステムの選択）まで遡ることになります。
  - 外部ファイルシステムの場合は、途中はスキップしてファイルシステムのルートまで遡ります。ファイルシステムのルートに移動できない場合は、ルート（ファイルシステムの選択）まで遡ることになります。
