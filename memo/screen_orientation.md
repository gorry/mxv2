スキンの縦横切り替え機能を追加します。

## 基本方針

- プラットフォームごとにこの機能が使用できるか否かが異なりますが、形としては全プラットフォームで実装し、アプリ起動時のオプションで機能を使用するかどうかを選ぶことにします。
  - デフォルトは、デスクトップ用ではOFF、モバイル用ではONとします。現状では、Windows（タブレットも含む）がOFF、Android（スマートフォン/タブレット）がONとなります。
  - デスクトップ用でこの機能をONにした場合は、縦横の検出はダミーとして常にどちらかを返すようにし、縦横切り替えのメッセージがアプリに渡ってくることもない、という動作になります。
- 機能をONにした場合は、以下のような動作となります。
  - 縦用と横用の2つのスキンを設定しておき、端末の縦横に応じてスキンを切り替えられるようにします。
    - スキンの変更の反映は、機能OFF時と同様に即時行います。
  - 切り替え機能は、3段階を用意します。
    - **切り替えない**: 常に縦画面か横画面かどちらか固定でスキンを選んで起動します。以後の縦横の切り替えには反応しません。ただし上下反転には反応します。
    - **起動時のみ切り替える**: 縦横どちらの状態で起動したかでスキンを選びます。以後の縦横の切り替えには反応しません。ただし上下反転には反応します。
    - **常に切り替える**: 縦横どちらの状態で起動したかでスキンを選びます。その後も縦横の変化に応じてスキンを切り替えます。

## 設定画面

- 機能をONにした場合は、以下のような動作となります。
  - [mxv2 の設定]のスキン選択部を、縦画面用と横画面用の2つのスキン選択に拡張します。
    - layout.iniの[Screen].Width/Heightで、縦長なら縦画面用、横長なら横画面用と区別します。正方形の場合は縦画面用とします。
    - 縦画面用のドロップダウンには縦画面用、横画面用のドロップダウンには横画面用のスキンを優先的に上にまとめて表示します。
      - スキン名の前に縦横どちら用のスキンであるかを示す印を表示しておきます。縦長四角形(U+25AF) / 横長四角形(U+25AD)がフォントに含まれていれば、それを使用します。
        - フォントに上記UNICODEが含まれていなかった場合は、代替として"|"と"-"を使用します。
      - 縦画面用に横画面用スキン（またはその逆）を選んだ場合、画面に余白が発生しますが、ユーザーの選択として許容します。
      - 初期値はプラットフォームで変えます（2026-09-12 に決定）。
        - デスクトップ: 縦画面用「Default-Portrait」、横画面用「Default-Landscape」（どちらも Default を土台にした実体。デスクトップでは切り替えがデバッグ用なので、この 2 つもデバッグ用）。
        - モバイル: 縦画面用「Phone」、横画面用「Phone-Landscape」（旧 Phone-R）。切り替え OFF のときの「Default」相当は「Phone」で、こちらはデバッグ用。
        - どれも、存在しない場合は「assets:Default」へフォールバックします。
  - 切り替え機能の選択を用意します。
    - 「縦画面のみ」「横画面のみ」「起動時の方向で切り替える」「常に切り替える」の4つを用意します。初期値は「常に切り替える」とします。
      - 「縦画面のみ」「横画面のみ」は、「切り替えない」のユーザー側への見せ方として分けています。
      - 実際の動作切り替えは「ダイアログを閉じた後」とします。ダイアログにも注記します。
        - 「起動時の方向で切り替える」設定の場合は、ダイアログを閉じた時の方向で切り替えることになります。

## その他

- 機能のオプション名は`-orient`とします。1でON、0でOFF、初期値はプラットフォーム毎に変わります。
  - `-orientlock`で、機能がONのときに「スキンを選ぶための方向として固定値を返す」ようにします。0でセンサーの方向を返す（このオプションの機能をOFF）、1で縦長、2で横長を常に返すようにします。初期値は0です。
    - デスクトップの場合、0は横長を返すものとします。
    - このオプションは、回転の制御には反映されません。スキンの選択においてのみ反映されます。
- mxv2.iniには、機能ON時用とOFF時用の設定を個別に残します。既存の設定は「OFF時用の設定」として流用します。機能のON/OFFそのものは保存しません。
  - [Screen].SkinPortraitで縦画面用のスキン名を保存します。
  - [Screen].SkinLandscapeで横画面用のスキン名を保存します。
  - [Screen].Orientationで切り替え機能の選択を保存します。
- Androidでは、ユーザーとしてはコマンドラインオプションを与えられないため、この機能は常にONとして動作します。デバッグ時にはオプションを与えることができるため、OFF時の動作はデバッグ時専用となります。
- "-skin"オプションを付けての起動の場合、自動的にこの機能をOFFにします。
- Androidの場合、「縦横の切り替えには反応しないが、上下反転には反応する」をSCREEN_ORIENTATION_SENSOR_PORTRAIT/SENSOR_LANDSCAPEの設定で行うのが簡単です。


## 実装で決めた細部（2026-09-10）

仕様に書かれていないところは、以下のとおりに決めた。

- **`[Screen] Orientation` の値は文字列**で書く（`PortraitOnly` / `LandscapeOnly` /
  `Startup` / `Always`）。mxv2.ini を手で編集する人に分かるように、また
  layout.ini の `[Screen] FilerSide` を文字列にしたのと同じ流儀に揃えるため。
- **いま表示していない側のスロットのスキンを変えたときは、ini を更新するだけ**
  （画面は変えない）。「即時反映」は、表示中の向きに対応するスロットの話。
- **ini に書かれたスキンが無いときは、警告を出したうえで、その系統の既定の
  スキンへ落とす**（2026-09-12 に改めて決めた）。落とし先はデスクトップ／
  モバイルで違い（上の初期値と同じ。`settings.cpp` の `kDefaultSkin*`）、
  切り替え OFF なら `Skin` の既定、ON なら縦・横それぞれの既定。それも読めない
  ときだけ最後に `assets:Default`。起動時・回転時・設定を閉じたときの
  切り替え、素材が足りなくて描けなかったときの逃げ、すべて同じ
  （`main.cpp` の `DefaultSkinFor`）。
- **フォールバックは ini に書き戻さない**（切り替え OFF のときも。以前は OFF の
  ときだけ `Skin=assets:Default` を書き戻していた）。`Skin` / `SkinPortrait` /
  `SkinLandscape` に書いてある名前はそのまま残す（スキンを置き直せば次の起動で
  戻ってくる）。
- **機能 OFF のときの初期スキン**（`[Screen] Skin`）は今までどおり
  `#ifdef __ANDROID__` で `Phone` / `Default`（`settings.cpp`）。OFF はデバッグ
  専用になったので、ここは変えない。
- **向きの供給源はひとつの窓口に閉じ込める**（`Screen::orientation()` /
  `Screen::DisplayOrientation()`）。中で「`-orientlock` の指定 → デスクトップの
  ダミー → 実物」の順に決めるので、呼ぶ側はどれが効いているかを知らない。

## 実装上の注意（調べて分かったこと）

- **Android の向きは `SDL_GetDisplayOrientation` で採らない。**
  `SDLActivity.getCurrentOrientation()` は `display.getRotation()`（＝端末の
  **自然な向き**からの回転量）をそのまま写しているので、**横が自然な向きの
  タブレットでは、横に持っているのに `PORTRAIT` が返る**。
  代わりに**出力（ウィンドウ）の `w > h`** で決める。端末を問わず正しく、
  fullscreen.md の「キャンバスが窓に追従する」とも整合する。
  デスクトップは窓を自由に変形できるので縦横比では決められない
  （変形のたびにスキンが入れ替わってしまう）。ダミーで常に横を返す。
- **回転の制御には JNI ブリッジが要る。** `SCREEN_ORIENTATION_SENSOR_*` を
  実行中に切り替える手段が SDL には無い——`SDL_HINT_ORIENTATIONS` は
  ウィンドウ生成時と `SetWindowResizable` でしか読まれず
  （`SDL_androidwindow.c`）、`SDL_SetWindowResizable` は**フラグが変わるときしか**
  バックエンドを呼ばない（`SDL_video.c`）。`SafBridge` / `PlaybackBridge` と
  同じ形で `Activity.setRequestedOrientation` を叩く窓口を足す。
  「常に切り替える」は `SCREEN_ORIENTATION_FULL_USER`（＝今までの状態）。
- **スキンの縦横分けには `Skin::Load` を通す。** `AssetPaths::ListSkinRefs` は
  名前しか返さず、`Default-Midnight` のように **Base から画面サイズを
  継承しているスキン**は、名前や layout.ini の直読みでは分けられない。
  [再読込] でも測り直す。
- **回転したときの適用順。** スキンの差し替えを、キャンバスを窓へ合わせる
  処理（`SyncCanvasToWindow`）**より前**に置くこと。逆だと、キャンバスだけ先に
  追従して 1 フレームぶん「旧スキンが引き伸びた絵」が出る。
- 「ダイアログを閉じた」は `SettingsUi` の表示フラグが落ちるのを見れば分かる。
- メインメニュー（右クリック / バナー）を出している最中に画面が回転してスキンが
  替わるときは、メニューを閉じる（`SettingsUi::CloseContextMenu()`）。
  理由: 回転させるとメニューが画面をはみ出すことがある。再計算して配置し直しても
  よいが、それより閉じてしまったほうがスマート。ダイアログは回転時に置き直す
  （下記）ので、そのまま残す。
  閉じるフレームではメニューの項目を組み立てない（`BuildContextMenuItems` を
  呼ばない）。続けて `BeginMenu` を通すと、指の位置がサブメニューの見出しに
  重なったままなら閉じた直後にサブメニューを開き直し、親の無いポップアップが
  ImGui に残ってタッチが効かなくなる（2026-09-16、横画面で [表示] を出したまま
  縦にすると操作不能、の原因）。
- **ダイアログは、表示サイズが変わったフレームに矩形ごと置き直す**（2026-09-11）。
  当初は [mxv2 の設定] だけが倍率変更のときに置き直していて、他のダイアログは
  開いたときの位置と大きさのまま（ImGuiCond_Appearing）だったので、回転すると
  画面からはみ出したままになった。`SettingsUi::placeCond()` が「倍率が変わった」
  「`io.DisplaySize` が前フレームと違う」フレームだけ `ImGuiCond_Always` を返し、
  **すべてのダイアログ**（入れ子の確認も含む）が `CenterNextWindow` と
  `SetNextWindowSize` にこれを渡す。以後 `ImGuiCond_Appearing` を直に書かないこと。
  Pixel 7a で [ブックマークの設定] を開いたまま縦→横→縦と回して確認済み。
  既存の `TakeChangedFields()` / `TakeLocaleChanged()` と同じ形にする。
- 起動時の向きは間に合う。初期化順は
  `settings.Load` → `ParseArgs` → `SDL_Init(VIDEO)` → `skin.Load` → `screen.Open`。
- 印に使う U+25AF / U+25AD は**同梱フォント (MPLUS1p-Regular.ttf) に入っている**
  ことを確認済み。設定ダイアログは必ず同梱フォントを使うので出せる。
  出せないのは同梱フォントが失われて ImGui の既定フォントに落ちたときだけで、
  そのとき `"|"` / `"-"` にする。

## 波及範囲

- `src/settings.h/.cpp` … ON 用のキー 3 つ・初期値・保存ビット
- `src/settingsui.cpp` … [スキン] グループが ON/OFF で 2 つの姿を持つ。印つきの
  並べ替え、`Skin::Load` での分け、モード変更の遅延適用と注記
- `src/main.cpp` … `-orient` / `-orientlock` の解析、起動時の選択、回転の検出、
  適用順
- `src/screen.h/.cpp` … 向きの窓口
- `src/orientation.h/.cpp` + `android/` … 回転の制御（JNI）。manifest は変更なし
- `assets/locale/*/message.ini` … オプション 2 行、設定画面の文言と注記
- `readme.md` … スキンの節（同梱スキンが 4 → 6 個に増えたぶんも）
- `android.md` … 保留事項「画面の向きとスキン」の消化
- **スキンエディタは無関係**（layout.ini のスキーマは変わらない）
