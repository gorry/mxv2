mxv2 で使用するスキンを編集するアプリを作成します。

## スキンエディタ

- mxv2本体とは別に、スキンエディタを作成します。
- Windowsで使用する、GUI型アプリです。 C# で作成します。
- mxv2本体のスキン表示を模した画面と、その上で各素材の配置位置を設定できる機能、また各素材の表示パラメータの設定が必要です。
- 各素材のビットマップ編集機能は不要です。外部で作成します。

## 動作の流れ

1. assets/ フォルダがあるディレクトリで起動します。mxv2本体の CMakeLists.txt があるディレクトリか、mxv2.exe のあるディレクトリかですが、この2つでは動作が変わります。
   - 前者（**開発フォルダモード**。2026-09-14 に命名。起動時の文言は「開発フォルダモードで起動しました。mxv2同梱のスキンを直接編集します。」「編集するスキンのフォルダ: <CMakeLists.txt のフォルダ>\assets\skin」「スキンの一覧:」）では、編集対象のスキンは、開発フォルダ（mxv2本体の CMakeLists.txt のある場所）の assets/skin/ にあるスキンとなります。編集内容はすべてアプリ組み込みになります。[Skin].Base の参照先は、必ず「assets:...」となります。
   - 後者では、編集対象はユーザーフォルダ上のスキンとなります。mxv2.exe 組み込みのスキンはすべて参照先としてのみ指定可能で、編集はできません。[Skin].Base の参照先は、組み込みスキン・ユーザーフォルダのスキンのどちらも指定可能です。
     - 後者は**ユーザーフォルダモード**。**2026-09-14 に実装した。** 判定は「assets/ の
       隣に CMakeLists.txt が無い」こと（mxv2.exe の有無は見ない）。編集先は
       mxv2 本体と同じユーザーフォルダ（Windows なら `%APPDATA%\mxv2\skin\`）で、
       `SkinEditor.exe -userdir <dir>` で差し替えられる（検証用。本体の
       `-userdir` と同じ流儀）。起動フォルダは引数でも渡せる。
       一覧に出るのはユーザーフォルダのスキンだけで、同梱のスキンは
       [新規作成] の「元にするスキン」と「参照先スキン」の候補に
       `assets:<名前>` として並ぶ（ユーザーのスキンは `<名前>`）。
       Base の解決は本体の `AssetPaths::SkinDir` と同じ（接頭辞なしは
       ユーザーのスキンがあればそれ、無ければ同梱）。ユーザーのスキンと同梱の
       スキンが同名でも別物として扱う（循環ではない）。
       文字（font.ttf）の探索も本体と同じ順（スキン → ユーザーフォルダ →
       同梱 assets/）。
       起動時の一覧ウィンドウの文言は「ユーザーフォルダモードで起動しました。mxv2同梱の
       スキンは参照のみ可能です（編集できません）。」「編集するスキンのフォルダ: …」
       「スキンの一覧:」の 3 行。ウィンドウの初期サイズは横幅 = 文面のいちばん長い行の
       幅の 1.2 倍、縦幅 = 横幅の 9/16（2026-09-14、ユーザーの指示）。
       モードは起動したフォルダで一律に決める（[フォルダを選ぶ…] は廃止。[再読込] は
       [スキン一覧の再読み込み] に改名）。どちらでもなければダイアログ「「mxv2.exeのある
       フォルダ（ユーザーフォルダモード）」か、「CMakeLists.txtのあるフォルダ（開発
       フォルダモード）」で起動してください」を出して終了する。
2. スキンの一覧を取得します。
3. 編集するスキンを選ぶか、元となるスキンを選んで新規に作成するかを選びます。
4. スキンを開いて編集を行います。ユーザーによる保存が発行されるまで、編集中の内容は保存されません。
5. 編集中の内容がある状態で、編集の終了が発行された場合、「保存して終了」「保存しないで終了」「キャンセル」のいずれかを問い合わせます。
6. 編集を終了したら、2.に戻ります。

## 編集内容

- **layout.ini**: mxv2本体で扱う要素は基本的にすべて扱うものとします。mxv2本体の skin.cpp/.h と合わせてください。
- **colors.ini**: layout.ini と同様です。
- **各素材のビットマップファイル**: 
  - ビットマップファイルから各パーツを抜き出すための座標設定などを、GUIで設定できるようにします。
  - layout.ini の仕様としてはファイル名を任意に指定できることになっていますが、既定から変更しないものとします。外部からインポートする場合は、既定のファイル名にリネームする形をとります。
  - ビットマップのサイズは任意のものを使用できます。インポートした直後など、座標がビットマップの外になる可能性があるので、適切にクリップする必要があります。
  - 素材は外部のツールで編集するので、**同じファイルを描き換えたときにプレビューへ反映させる手段**が要ります。ツールバーの「素材の再読み込み」で、読み込み済みの素材（*.bmp と font.ttf）を捨てて読み直します。layout.ini と colors.ini は読み直しません（編集中の値のほうが新しいため）。

## Baseによる参照

- [Skin].Base で、編集中のスキンが持っていないデータの参照先を指定する（または無参照にする）ことができます。これを変更した時の動作は、以下のようになります。
  - 無参照から参照に切り替えるときは、切り替えを実行するかどうかを確認します。実行が選ばれたときは、切り替えを行ったあと、編集中の内容の保存を行います。
  - 参照から無参照に切り替えるときは、切り替えを実行するかどうかを確認します。実行が選ばれたときは、「参照先のスキンから読み込んでいたデータ」を編集中のスキン側にコピーした後で、編集中の内容の保存を行います。


## フォントのインポート（2026-09-14、ユーザーの指示）

- スキン一覧のウィンドウに [バージョン情報…] ボタン（2026-09-15、ユーザーの指示）。
  名前・バージョン・ビルド日付・著作権をダイアログで出す。値は `mxv2/Profile.ini` の
  `[Title] Text-SkinEditor` / `[Version] Text`（本体と同じ）/ `[Copyright] Text-SkinEditor`
  で、csproj がビルド時にアセンブリ属性へ写す（`Model/AppProfile.cs`）。
- 「ミニフォント」タブを「フォント」タブに改名し、一番上に「素材: TTFフォント (font.ttf)」を置く。
  他の素材行と同じく、チェックボックスで自スキン／継承を切り替え（OFF は `_nouse` へ退避、
  ON は Base 側の実体を複製）、[インポート…] で TrueType フォント (*.ttf) を選ぶと自スキンの
  `font.ttf` へそのまま複製する（変換はしない。GDI+ で読めるかだけ検査する。本体は
  stb_truetype で読む）。本体の規則も素材ビットマップと同じ「スキンのフォルダにあれば使う、
  無ければ Base のフォルダ」で、`layout.ini` には書かない。
- インポート後はプレビューの文字（曲名・ファイラー）がそのフォントで描き直される。

## layout.ini / colors.ini のコメント保持（2026-09-15、ユーザーの指示）

- 保存時にコメント・空行・行の並びをそのまま残し、キーの値だけを差し替える
  （`Model/IniDocument.cs`）。それまではセクションとキーだけを書き出していたので、
  開発フォルダモードで同梱スキンを保存すると説明コメントが全部消えていた。
- 既存のキーは元の行の位置で `Key=Value` に書き換え、消したキーは行ごと消す。
  新しいキーはそのセクションの最後のキー行の直後、新しいセクションはファイル末尾。
- 文字コードは UTF-8（BOM なし）、改行は LF に揃える。参照の切替（無参照化）や
  colors.ini の保存も、元のファイルの上に書く。
